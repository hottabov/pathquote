## 1. Purpose

Production order forms are currently generated by patching the original Excel workbooks: each form spec maps values and ticks onto hard-coded cell addresses (`G8`, `H13`, `J82`, `F42`…`O57`), the patched workbook goes to LibreOffice inside Gotenberg, and the resulting PDFs are merged.

This spec replaces that with forms rendered as HTML from React components — the same pipeline the quotation PDF already uses (`src/lib/pdf.ts` → Gotenberg's Chromium module).

The data half of the existing spec — where a form comes from, when it may be generated, `lineGroup`, `Industry`, the Additional items sheet, option-coverage reconciliation — is unchanged and still authoritative.

## 2. Why

**The cell map is silently fragile.** A production manager who inserts one row into a template shifts every address below it. Nothing throws: the form renders, the `X` lands in the wrong box, and the workshop builds the wrong machine. The templates are binary, so the change is invisible in a diff.

**The medium is leaking into the domain.** Three artefacts in the current code exist only because Excel behaves the way it does, not because the business requires them:

- `N8` instead of `M8`, `O11` instead of `N11`, `O10` instead of `N10` — the label cell is too narrow and relies on overflowing rightward, so writing into the obvious cell clips it to `"Nam"`.
- 22- and 28-character caps on the drills detail and the special notes, enforced in the Zod schema, because rows 81–82 carry a large font and the two columns collide.
- `replaces: J35` on the EasyLoader — the only place in the engine that overwrites *printed label text*, because the custom-width row has no blank beside it.

Each is now a rule a salesperson has to obey for a reason nobody can explain.

**Every form looks slightly different.** Thirteen workbooks, edited over years by different people. There is no shared header, no consistent tick box, no common type. PathQuote already has a visual system; the forms are the only output that does not use it.

**The remaining work is the same size either way.** Ten forms are still unwritten. Transcribing one into cell addresses and transcribing one into a component tree cost about the same — but the second is readable in a pull request.

## 3. Scope

**In scope:** M-Series, EasyLoader, FabricPro, X-Calibre, L-Series. The first three replace working xlsx-backed forms; the last two are new and have no implementation today.

**Out of scope, same engine later:** Punchline, EasyFeeder, HDRF, FabricPro Trolley, Leather Nesting Station, Software Order Form, Miscellaneous, Machine Payment Record. Each is one component file plus its entry in the registry.

**Never in scope:** the "Office Use Only" block on every form. It is filled by hand in the workshop and stays blank by design — now rendered with dashed rules and a distinct ground so that "not ours to fill" is visible rather than conventional.

## 4. Decisions taken

| Question | Decision | Rationale |
|---|---|---|
| Rendering | React → `renderToStaticMarkup` → Gotenberg Chromium | Already proven by the quotation PDF. One pipeline, one set of failure modes. |
| Layout fidelity | Field **order and grouping** are preserved exactly; typography, rules and boxes are new | Workshop staff scan these from memory. Moving the knife size loses that; restyling it does not. |
| How a form is defined | A React component, plus a small declarative record for matching and coverage | See §7. The layout differences between forms are real; the option-coverage rules must stay machine-readable. |
| Units | Millimetres throughout the sheet | The output is A4. `px` invites a DPI assumption; `pt` is for type only. |
| Fonts | Arial / Helvetica / Liberation Sans stack | Guaranteed present in the Gotenberg container and matching the quotation sheet. A webfont would have to be inlined as a data URI or it substitutes silently. See §13. |
| Multi-form output | One HTML document with page breaks, one Gotenberg call | Removes `mergePdfs` and its zero-padded-filename ordering workaround. |
| Character limits | Removed | They were properties of Excel row heights. Long values wrap; contact data never ellipsises (§5.4). |
| Blank forms | Supported, `?blank=1` | Falls out of the design for free and lets production stop keeping the xlsx files for printing empty sheets. |
| Print | New route, `window.print()` | Downloading a PDF in order to print it is a detour the browser does not need. |

## 5. The visual system

### 5.1 Tokens

Every form declares the same token block on the sheet root. Values are the PathQuote brand colours plus a set of neutrals biased toward the navy, so the greys sit *under* the brand colour rather than beside it.

```
--ink        #16181f    body text
--ink-soft   #4b5162    secondary text, option descriptions
--label      #6d7488    uppercase field labels
--rule       #c2c7d6    value underlines, borders
--rule-soft  #dde1ec    column dividers
--tint       #eef0f7    section header ground
--tint-hit   #e7ebf7    selected option row
--tint-std   #f2f3f6    standard-fitment row
--box-line   #949ab0    unticked box border, standard-fitment fill
--navy       #243478    brand, section headers, ticked box
--alarm      #a41f1f    "TBC not accepted", handling instructions
--bx         3.6mm      the one tick-box size on the sheet
```

### 5.2 Type scale

Six sizes, no others: `5.9pt` field labels · `6.2pt` provenance and footnotes · `6.5pt` section headers · `7.6pt` option text · `8.6pt` values · `13pt` form title. Uppercase labels carry `0.1em` tracking; section headers `0.15em`. Every column of digits gets `font-variant-numeric: tabular-nums`.

### 5.3 The tick box

One size everywhere — `--bx` — regardless of the surrounding text size. Four states:

| State | Appearance | Meaning |
|---|---|---|
| Empty | White, hairline border | Not ordered |
| Ticked | Navy fill, white check | Ordered on this quote |
| Standard | Grey fill, white check | Fitted to every machine of this model; not a choice (X-Calibre's IKA/AFP/HFV, L-Series' MRK) |
| Quantity | Navy fill, white figure | L-Series tools, where the printed form says to replace the mark with a number when more than one is required |

The check is drawn with two CSS borders on a rotated box, not a glyph: a font character would depend on the PDF renderer having that font. It is nudged up by `0.28mm` because a checkmark's optical centre sits below its geometric one.

Standard fitment is deliberately grey. Navy on these sheets means "someone chose this on this quote"; marking permanent fitment the same way sends the workshop looking for a decision that was never made.

### 5.4 Rules that hold across all forms

- **Contact data never ellipsises.** An abbreviated email is a wrong email. Email fields wrap at any character; everything else truncates.
- **The masthead is identical on every form** — logo, title with a `PRODUCTION ORDER` eyebrow, contact block — so a stack of forms reads as one set.
- **`+Y` sits above `−Y`,** always, on every form that offers the choice.
- **An illustration, where a form has one, sits to the right of the machine-choice block.** Nowhere else.
- **Ordered options get a tinted row band,** so what was bought reads at a glance across a page of thirty boxes.
- **Every sheet carries a provenance line:** form id, revision, quote number, item *n* of *m*, generation date. The paper forms had none, and the workshop could not tell which quote a sheet came from.

### 5.5 Print colour

Browsers drop background colours when printing, which would erase every filled tick box and every section header band. The sheet sets `print-color-adjust: exact`, and the Gotenberg call must pass `printBackground`. This is the single highest-consequence detail in the spec: without it the forms print as empty boxes and nobody notices until the workshop builds from one.

## 6. Component inventory

```
src/components/production-forms/

  masthead.tsx       Masthead                logo · title · contact
  field.tsx          Field, FieldLines       labelled value; multi-line address block
  tick.tsx           Tick                    one box; state: on | std | qty | empty
  tick-grid.tsx      TickGrid                columns, dividers, row bands
  section.tsx        Section, SectionRow     header band; two sections sharing a row
  write-in.tsx       WriteIn                 drills, special notes
  office-block.tsx   OfficeBlock             dashed hand-filled block
  measured.tsx       Measured                inline ruled run + unit
  provenance.tsx     Provenance              footer identity line
```

The CSS lives in one `SheetStyles` string next to `Sheet`, embedded as a `<style>` element — the same constraint `document-sheet.tsx` and `quotation-sheet.tsx` already work under (no Tailwind, no external stylesheet, because Gotenberg's Chromium fetches nothing).

## 7. How a form is defined

A form is a React component plus a small record. The split is deliberate:

```ts
export type FormDefinition = {
  id: string;                       // "m-series"
  title: string;                    // "M-Series Order Form"
  revision: string;                 // "12" — printed in the provenance line
  matches: (code: string) => boolean;
  specSchema: z.ZodTypeAny;
  requires: string[];               // productionSpec keys that block generation
  /** Option-code patterns this form has a box for. */
  covers: RegExp[];
  /** Options the form accounts for without a box of their own. */
  coversOptions?: RegExp[];
  Component: (props: { ctx: FormContext; blank?: boolean }) => ReactElement;
};
```

**Layout is JSX** because the forms genuinely differ — the EasyLoader's table-section rows, X-Calibre's standard-fitment column, L-Series' consumables reference block. A generic schema able to express all of them would be a worse language than JSX, and would grow a special case per form anyway.

**Coverage stays declarative** because `unmatchedOptionCodes` must be able to ask "does this form have a box for option X?" without rendering it. That question is what keeps a sold option from silently vanishing instead of appearing on the Additional items sheet, and it is the safety-critical part of the engine. Today the answer is assembled from `covers` on each tick; under JSX the ticks are no longer enumerable, so the patterns move up to the definition as one list.

This is the one real cost of the change, and it is worth naming: `covers` and the JSX can drift apart. A test asserts that every pattern in `covers` is mentioned somewhere in the component's rendered output for a fixture item, which catches the common case of deleting a tick and forgetting its pattern.

### 7.1 What is deleted

`xlsx-patch.ts`, `cell-ref.ts`, `readTemplate`, `xlsxToPdf`, `mergePdfs`, the `values` / `replaces` / `ticks` cell arrays in all three specs, and the three `.xlsx` templates. The `xlsx` dependency stays — `scripts/extract-catalog.ts` uses it.

### 7.2 What survives unchanged

`context.ts` (`buildFormContexts`, `companyAddressLines`), `table-sections.ts`, and the reconciliation logic in `resolve.ts`. These are about the quote, not about Excel.

## 8. Data contract

### 8.1 `FormContext` additions

Three fields the paper forms did not carry and the mockups now print:

```ts
type FormContext = {
  /* …existing… */
  documentNumber: string;    // "Q-AU-2026-014" — meta strip and provenance line
  itemIndex: number;         // 1-based, for "item 2 of 3"
  itemCount: number;
  generatedAt: Date;
};
```

`Mobile` and `Fax` are dropped from every form. A quote carries one phone number, and fax is dead.

### 8.2 `productionSpec` for the two new forms

```ts
// X-Calibre — same shape as M-Series minus knifeSize (one size, fixed)
{ ui: "+Y" | "-Y",
  voltage?: "220V" | "400V" | "415V" | "480V",
  drills: { required: boolean; detail: string },
  specialNotes?: string }

// L-Series
{ ui: "+Y" | "-Y",
  cuttingLength: "175" | "316",
  cuttingSurface: "felt" | "urethane",
  modelOther?: string,                 // free text beside the printed models
  voltage: "220/230" | "other",
  voltageOtherVac?: string,            // required when voltage === "other"
  tools: Record<string, number>,       // tool code → qty; absent or 0 = not ordered
  shipping: "complete" | "crate-disassembled" | "crate-whole",
  specialNotes?: string }
```

`tools` as a quantity map is new: no existing form records a count per option. It is what the printed L-Series form asks for.

X-Calibre's shape is provisional. Production and the directors have not yet issued firm specifications for that machine (owner's note, 2026-09-03), so the form is built from the workbook as it stands and will be revised.

## 9. Rendering and routes

### 9.1 PDF — existing route, new body

`GET /api/documents/[documentId]/production-forms` keeps its contract: FINAL quotes only, `?item=<itemId>` narrows to one form and suppresses the Additional items page. What changes is the middle: instead of patching *n* workbooks, converting each and merging, it renders one HTML document containing every form separated by `break-after: page`, and makes one Gotenberg call.

`htmlToPdf` needs a `printBackground` option. It is currently absent, and the quotation PDF does not want it, so it becomes a parameter rather than a default.

No Gotenberg footer: the provenance line lives inside each sheet, so page numbering across a merged document is not needed.

### 9.2 Print — new route

`GET /documents/[documentId]/print/production-forms` renders the same components as a normal page and calls `window.print()` on mount. Same auth and same FINAL check as the PDF route.

This is the change that makes the daily path shorter: today printing means generating a PDF, downloading it, opening it, and printing that.

### 9.3 Blank forms

`?blank=1` on either route renders the same components with values suppressed and ticks cleared. Reachable from the forms section as "Print blank form", which removes the last reason to keep the workbooks around.

## 10. Migration

1. Build the component set and the five forms behind the existing route.
2. **Sign-off gate.** Print the old and the new for the same finalized quote and put them side by side in front of production. The originals stop being the source of truth at this point, so somebody has to say so out loud. Until this passes, nothing is deleted.
3. Delete `xlsx-patch.ts`, `cell-ref.ts`, the xlsx branches of `render.ts`, and the three templates. Keep the workbooks in `RAW/Order Forms/` — they are the historical reference.
4. Add the print route and the blank-form option.
5. X-Calibre and L-Series ship after their `productionSpec` editors exist in the builder.

No feature flag. Two rendering paths for the same document would need two sets of tests and would invite the question of which one is authoritative — the sign-off gate answers that question once instead.

## 11. Testing

- **Per form: an HTML snapshot** for a fixture quote. A cell-map regression was previously invisible; a snapshot diff is not.
- **Coverage test:** every pattern in `covers` appears in the rendered output for a fixture carrying that option (§7).
- **Unmatched options:** an option with no box still reaches the Additional items sheet. This is the existing behaviour and the most important thing not to break.
- **Code parsing:** the M-Series regex over all sixteen codes, as today.
- **Requirements gating:** a missing `drills` still blocks generation and disables the button.
- **Print fidelity** is checked by eye, once, at the sign-off gate. It is not automatable and pretending otherwise would waste a day.

## 12. Deliberately not doing

- **A form builder UI.** Adding a form is a pull request, not a runtime feature. Nobody has asked to add forms without a developer.
- **Re-drawing the workbooks' diagrams as SVG.** The ±Y and MTS images are low-resolution rasters and print soft. Worth doing; not worth blocking on. Tracked in §13.
- **Per-region form variants.** No evidence any exist.
